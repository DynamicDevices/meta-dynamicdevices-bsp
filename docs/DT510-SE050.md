# DT510 — SE050 (same stack as Jaguar Sentai)

## SSOT (hardware doc)

- **SE050** on **I2C4**, **7-bit address `0x48`** — bus and address match the [VIX DT510 pinout](https://docs.google.com/document/d/1dlVcfW7SrOifR-rGjkJnVbnQBO4uU8HeS1MEfDmgcYE/edit?usp=sharing) and Sentai.
- **Pin mux note (2026-07, Michael):** on i.MX8MM, **I2C4 uses dedicated pads only** (`I2C4_SCL` / `I2C4_SDA`, SoC balls **D13 / E13** → U31). **`SAI1_RXD2` / `SAI1_RXD3` are not I2C4** — they are **ENET_PME#** / **QUART_RES#** (GPIO) in the Google Doc and in `imx8mm-jaguar-dt510.dts`. Do not confuse **SE050 IC pin numbers** (e.g. U31 D13/E13) with **SoC BGA** names.

## Software stack (already correct for DT510)

DT510 uses the **same SE05x / OpTEE configuration** as **`imx8mm-jaguar-sentai`** (and other Jaguar boards with **`se05x`**):

- **`meta-dynamicdevices-distro`** / **`optee-os-fio`**: **`CFG_CORE_SE05X_I2C_BUS=3`**
- On i.MX8M, **bus index `3`** is the **fourth** I²C controller — i.e. **Linux `&i2c4`**, not `&i2c1`–`&i2c3`.
- The bbappend documents this: *if DeviceTree is e.g. **i2c4**, OpTEE uses the corresponding bus index* (pinmux for SE050 is initialised in OpTEE).

So **Ollie’s “I2C4 @ 0x48”** is **aligned** with the **existing SE050 implementation**, not a different bus.

## Machine configuration

`conf/machine/imx8mm-jaguar-dt510.conf`:

- **`MACHINE_FEATURES`** includes **`se05x`** (when not `LOCAL_DEVELOPMENT_BUILD`)
- **`SE05X_OEFID:imx8mm-jaguar-dt510 = "0xA200"`** — same pattern as Sentai.

## Device tree note

- **Sentai** does not necessarily expose an **SE050 child node** under `&i2c4` in the kernel `.dts`; **OpTEE** talks to SE050 directly using **`CFG_CORE_SE05X_I2C_BUS`**.
- **DT510** now explicitly keeps Linux **`&i2c4` disabled** in `imx8mm-jaguar-dt510.dts` so the kernel does not claim or re-mux the dedicated **D13/E13** SE050 pads that OpTEE uses.
- Adding an explicit **`&i2c4`** + **`se050@48`** (or NXP binding) in DT510 is **optional** for kernel visibility / plug-and-trust; it does **not** replace the OpTEE bus configuration.

### Physical pins (i.MX8MM — Michael confirmed 2026-07)

On **MIMX8MM6**, **I2C4** muxes only to dedicated pads **`I2C4_SCL`** / **`I2C4_SDA`**. **SoC BGA balls D13 / E13** route to **SE050 (U31)** — Michael confirmed these are **SoC balls**, not SE050 package pin numbers. **I2C4 is not an alternate function of SAI1_RXD2 / SAI1_RXD3** on this SoC.

| Function | SoC pad | SoC ball | Notes |
|----------|---------|----------|--------|
| **SE050 I2C4 SCL** | `I2C4_SCL` | **D13** | OpTEE **`CFG_CORE_SE05X_I2C_BUS=3`**; Linux **`&i2c4` disabled** |
| **SE050 I2C4 SDA** | `I2C4_SDA` | **E13** | Same |
| **ENET_PME#** | `SAI1_RXD2` | **AG17** | GPIO4_IO4 in `imx8mm-jaguar-dt510.dts` — **not I2C4** |
| **QUART_RES#** | `SAI1_RXD3` | **AF17** | GPIO4_IO5 — **not I2C4** |

Reject any **summary table** (chat, schematic annotation, or secondary doc) that maps **I2C4 onto SAI1_RXD2/RXD3** — that alt does not exist on i.MX8MM. The Google Doc **ENET_PME#** row on **`SAI1_RXD2` / GPIO4_IO4** is **correct** and is **not** I2C4.

## Conclusion

The **DT510 SE050 placement** (I2C4, `0x48`) is **consistent** with the **existing factory SE05x / OpTEE** setup used on Sentai. Further work is mainly **optional DT completeness** and **lab validation**, not a different security architecture.

**Tier B4 (BSP):** No change required for parity with Sentai — explicit **`&i2c4` / `se050@48`** remains optional.

## Dev vs secured factory line (`foundries-se050-hsm`)

**`se05x`** (`MACHINE_FEATURES`) stays **enabled** on factory images — OpTEE SE050 stack, `pkcs11-tool`, `fio-se05x-cli` (unchanged).

**Registration policy** is a separate **`DISTRO_FEATURES`** flag in **`meta-subscriber-overrides`**:

| | Dev line (default) | Secured line (UAT / production) |
|---|-----|-----|
| **`DISTRO_FEATURES`** | no `foundries-se050-hsm` | `foundries-se050-hsm` |
| **`/usr/share/dynamicdevices/factory-features`** | empty | contains `foundries-se050-hsm` |
| **`production-test.sh` step 4b** | skipped | required before Wi‑Fi |
| **`lmp-device-auto-register`** | software keys if no `/etc/sota/hsm` | **fails** without `/etc/sota/hsm` |
| **Manual bench** | optional `provision-foundries-se050.sh` + `/etc/sota/hsm` still works | same |

Enable on a factory branch (e.g. UAT) in **`lmp-factory-image.bbappend`** or subscriber **`conf/layer.conf`**:

```bitbake
DISTRO_FEATURES:append = " foundries-se050-hsm"
```

Recipe **`vix-factory-features`** writes the runtime stamp at image build time.

## Manufacturing — Foundries HSM registration (secured line only)

When **`foundries-se050-hsm`** is set, factory units must register with Foundries using the **SE050** as HSM (not software keys). The **`se05x`** stack is already in the image; **provisioning is manufacturing step 4b** before Wi‑Fi / auto-register.

### Order on the line (`production-test.sh`)

| Step | Action |
|------|--------|
| **4b** | **`provision-foundries-se050.sh`** — init PKCS#11 token, generate device key, write **`/etc/sota/hsm`** |
| **5** | Wi‑Fi (**VixProduction**) — triggers **`lmp-device-auto-register`** with **`--hsm-module`** |
| **12** | Secure — verify HSM registration, then **`set-fio-passwd.sh`** + firewall |

**Critical:** Step **4b must run before step 5**. If the unit registers over the network first, it will bind a **software** identity and SE050 provisioning cannot be retrofitted without factory re-flash / re-register.

### PIN custody (do not commit PINs to git)

| Item | Policy |
|------|--------|
| **User PIN (`HSM_PIN`)** | Used by **`lmp-device-register`** and **`pkcs11-tool`** at provision + OTA |
| **SO PIN (`HSM_SOPIN`)** | Token initialization only — store in factory HSM / secure station, not in repo |
| **Delivery to device** | Station writes **`/run/factory/se050-pins.env`** (mode **600**) before provision, **or** exports **`SE050_HSM_PIN`** / **`SE050_HSM_SOPIN`** |
| **Template** | **`/usr/share/board-scripts/se050-hsm-config.template`** (empty placeholders) |
| **Bench only** | **`ALLOW_SE050_DEV_PINS=1`** uses Foundries doc example PINs — **never on production line** |

Example station file **`/run/factory/se050-pins.env`**:

```bash
HSM_PIN="<from factory HSM>"
HSM_SOPIN="<from factory HSM>"
```

### Scripts

| Script | Role |
|--------|------|
| **`provision-foundries-se050.sh`** | One-time SE050 + **`/etc/sota/hsm`** setup |
| **`lmp-device-auto-register`** (subscriber) | Reads **`/etc/sota/hsm`** → **`--hsm-module /usr/lib/libckteec.so.0`** |

PKCS#11 module: **`libckteec`** (OpTEE). Token label default: **`aktualizr`** (align with Foundries **`46-pkcs11-label.toml`**).

### Bench verification (Michael lab)

On a **sacrificial** or unregistered unit (no **`/var/sota/sql.db`**):

```bash
sudo mkdir -p /run/factory
# station PIN file or ALLOW_SE050_DEV_PINS=1 for doc example PINs only
sudo ALLOW_SE050_DEV_PINS=1 provision-foundries-se050.sh
# then connect Wi-Fi; check:
journalctl -u lmp-device-auto-register.service --no-pager | grep hsm-module
pkcs11-tool --module /usr/lib/libckteec.so.0 --list-token-slots
```

Registered lab boards (e.g. **hw-lab**) **cannot** run full provision without erase — use **`pkcs11-tool --list-slots`** / **`fio-se05x-cli --list-objects all --se050`** for read-only checks only.
